# 共通仕様

## ✳️ アプリのアップデート

### ✏️ アップデートのチェック

- アプリ本体は <https://github.com/treetips/tree-voice-assistant/releases/latest/download/update-info.json> を確認する。
- ツールは <https://github.com/treetips/tree-voice-assistant/releases/download/tools-latest/tools-info.json> を確認する。
- 起動時はダイアログを出さず、不足ツールの準備後にヘッダー右端の更新カードへ結果を反映する。
- About画面の `アップデートを確認` ボタンとメニューバーの `更新を確認` は、アプリ本体を同じ手動確認経路で扱う。
- 手動確認で更新なし・失敗時はダイアログで通知する。失敗時はヘッダーの更新カードを変更しない。

### ✏️ ヘッダー右端の更新カード

- 詳細ペインのツールバー右端に、アプリとツールを統合した1行のカプセル型 Liquid Glass を表示する。
- 更新ありの文言は次の3種類とする。

| 更新の状態 | ボタン文言 |
| ---------- | ---------- |
| アプリのみ | アプリの更新があります |
| ツールのみ | ツールの更新があります |
| 両方 | アプリとツールの更新があります |

- ボタンを押すと確認ダイアログを挟まず、利用可能な更新を開始する。
- 両方ある場合はツールを更新してからアプリのダウンロードへ進む。ツール更新に失敗した場合はアプリ更新を開始しない。
- 更新なしは `アップデートは有りません` と表示し、クリックまたは10秒後に非表示化する。

### ✏️ アプリ更新の場合

1. 青い更新カードのボタンからZIPのダウンロードを開始する。
2. ダウンロード中は受信バイト数に基づく進捗率を表示する。総バイト数が不明な場合は不確定のスピナーを表示する。
3. SHA-256検証、展開、ステージングの各段階を同じカードに表示する。
4. ステージングが完了すると緑の `アップデート完了` カードへ切り替わる。この時点では `/Applications` のアプリを置換しない。
5. `アプリ再起動する` を押した後、ステージング済みアプリを `/Applications/TreeVoiceAssistant.app` へ配置し、別プロセスで起動して旧プロセスを終了する。
6. 再起動せずに終了した場合、次回起動時に `~/Library/Application Support/tree-voice-assistant/updates` を掃除する。

### ✏️ ツール更新の場合

- ツールは `uv`、`mlx-audio` のプロジェクト定義・lockfile、`Irodori-TTS` のソース・プロジェクト定義・lockfileを個別に更新する。
- Python仮想環境と音声モデルは初回利用時に取得する。ツール更新だけでアプリを再起動しない。
- 更新中はSTT/TTSの新規実行を無効化し、実行中はツール更新を開始できない。
- 失敗時は赤いカードと `再実行` を表示し、完了済みツールの記録を残して未完了分だけをやり直す。

### ✏️ 失敗時

- ダウンロード、検証、展開、配置の失敗時は赤いカードへ切り替わり、エラーダイアログで理由を通知する。
- アプリの起動だけに失敗した場合は、再ダウンロードせず緑のカードから起動を再試行できる。
