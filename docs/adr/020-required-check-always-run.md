# 必須ステータスチェックのBuild & Testを常に実行する

- ステータス: 代替済み (Superseded)（ADR 023で置き換え）
- 影響範囲: `.github/workflows/ci.yml`
- 関連: ADR 019（Markdownのlint・フォーマットをrumdlで行いCIでチェックする）

## 背景

ブランチ保護のルールセット（`protection`）が `Build & Test` の合格を必須
ステータスチェックとして要求している一方、`ci.yml` は `paths` で
`TreeVoiceAssistant/**` 等の変更時しか実行していなかった。
ドキュメントやCI設定以外の変更しかないPR（例: PR #17）ではワークフロー自体が
起動せず、`Build & Test` が報告されないまま「チェック待ち」が解消されず、
マージできないゾンビ状態になった。
また `paths` はアプリに同梱するリポジトリ直下の `assets/` を対象にしておらず、
リソース変更でビルド・テストが走らない取りこぼしもあった。

## 決定

- `ci.yml` の `paths` 指定を廃止する。必須ステータスチェックは変更内容に関わらず
  常に実行・報告されるべきため、絞り込み自体をやめる。
- 実行タイミングは main へのpushとすべてのPRとする。
  - pull_request はベースブランチを問わない（積み上げPRでも検査が動く）。
  - push は main へのpushに限定し、featureブランチのpushはPRでの検査に任せる。
- ジョブ名 `Build & Test` は変更しない（ルールセットの必須チェック名と一致させる）。

## 代替案

- ルールセットから必須ステータスチェックを外す
  - 却下: Swiftの変更がビルド・テスト未実行のままmainにマージできてしまう。
- paths非該当時に同名ジョブで成功を報告するスタブワークフローを併置する
  - 却下: 同名のチェックが2系統になり、どの条件でどちらが報告したか追いにくくなる。
    実行は数分で済むため、常に実行する方が単純で確実。
- `paths` に `assets/**` 等を追加して広げる
  - 却下: 将来追加されるパスで同じ滞留が再発する。必須チェックは絞らない。

## 結果

- すべてのPRで `Build & Test` が実行・報告され、変更ファイルに関わらず
  必須チェックが満たされる。ゾンビ状態のPRは発生しない。
- main へのpushでも毎回実行されるため、マージ後の破損も検出できる。
- 本決定はADR 023で置き換えられた（Swift関連の変更時のみ実行し、
  非該当時はSkipped報告する方式に変更）。
