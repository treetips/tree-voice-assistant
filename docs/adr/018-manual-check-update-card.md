# 手動更新確認の結果をサイドナビ下部の更新カードにも反映する

- ステータス: Accepted
- 影響範囲: `Core/UpdateCheckController.swift`
- 関連: tree-image-optimizer ADR 0042（手動更新確認の結果をサイドナビ下部の更新カードにも反映する）

## 背景

更新確認の手動経路（About画面の `アップデートを確認` ボタン・メニューバーの `更新を確認`）は、
結果をダイアログとAbout画面内のメッセージでしか伝えていなかった。
一方、サイドナビ下部の更新カード（ADR 017）は起動時のサイレント確認でのみ更新されていたため、
手動確認の直後にもかかわらずカードの表示が古いまま残る、あるいは表示されないという不整合があった。
About画面のボタンを押したらサイドナビ下部の更新カードにも結果が出ることを求める要件が出た。

## 決定

- 手動確認（About画面のボタン・メニューバーの `更新を確認`）の結果を、従来のダイアログ・
  About画面内メッセージに加えてサイドナビ下部の更新カードにも反映する。
- 反映先の状態は1つに絞らず二重表示とする（ダイアログとカードの併用）。
  - 更新あり: インストール確認ダイアログと「更新あり」カードを同時に表示する。
    カードクリックでダイアログを再表示できる（`showInstallDialog`）。
  - 更新なし: 「最新です」ダイアログと「更新なし」カードを同時に表示する。
    カードの10秒後自動非表示（ADR 017）は手動確認でも同じ。
- 確認失敗時は更新カードを変更しない（`resolveManualCard(for:)` がnilを返す）。
  ネットワーク失敗で「更新なし」カードを出すと、同じ瞬に出る失敗ダイアログと
  食い違って「更新が無い」と誤解されるため。カードが既に表示されていれば
  直前の確認結果をそのまま残す。
- 更新確認結果→カード状態の解決は起動時用 `resolveCard(for:)` と手動用
  `resolveManualCard(for:)` の純粋関数に切り出し、単体テストで検証する。
- 経路ごとの分岐は持たず、About画面とメニューバーは同じ `checkForUpdate` を
  呼び出す構成を維持する（一貫性のため両方を同じ挙動にする）。

## 代替案

- ダイアログを廃止してカード表示に一本化する
  - 却下: インストール確認の意思決定はダイアログで行う現状フローが分かりやすく、
    カードはサイドナビを開かないと見えないため、通知経路が弱くなる。
- 手動確認の失敗も「更新なし」カードを表示する（起動時と同じ `resolveCard` で統一）
  - 却下: 失敗ダイアログと「更新なし」カードが同時に表示され、
    「チェックに失敗したのか・更新が無いのか」が分からなくなる。
- About画面だけ変更しメニューバーはダイアログのままにする
  - 却下: 同じ手動確認なのに結果の出どころが経路で変わり、状態が二重管理になる。

## 結果

- About画面・メニューバーの手動確認後、サイドナビ下部の更新カードに
  確認結果が表示される（失敗時は表示が変わらない）。
- 実装箇所: `TreeVoiceAssistant/TreeVoiceAssistant/Core/UpdateCheckController.swift`
- テスト: `UpdateLogicTests` に手動確認結果→カード状態の解決（失敗時nil）の単体テストを追加した。
